## Day 7 Priority 1 — Alpaca CLI Compliance

The selected integration preserves the Lockean trust boundary:

```text
Alpaca CLI
    ↓
read-only paper-account evidence
    ↓
Lockean normalization
    ↓
PaperAccountSnapshot
    ↓
Lockean Authority
```

Alpaca CLI does not:

- authorize recommendations
- create Authorization Receipts
- verify Authorization Receipts
- call the Execution Gateway
- submit broker orders

Authorization remains a Lockean responsibility.

The adapter fails closed on:

- live-trading environment configuration

The CLI subprocess has a finite 10-second timeout.

## Raw Account Endpoint Decision

Initial real testing with:

```text
alpaca account get --quiet
```

revealed that Alpaca CLI 0.0.14 omitted the `trading_blocked` property when its value was false.

Lockean did not interpret missing evidence as `False`.

A read-only diagnostic through the CLI raw API path showed:

```text
trading_blocked: False
```

as a real boolean.

The production adapter therefore uses:

```text
alpaca api GET /v2/account --quiet
```

This preserves strict validation rather than weakening the account-evidence contract.
